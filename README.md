# 📝 SecureNote App

โปรเจกต์ SecureNote เป็นแอปพลิเคชันสำหรับจดบันทึกย่อ ที่ถูกแบ่งสถาปัตยกรรมออกเป็น 2 ส่วนหลัก ได้แก่ **Frontend** (หน้าเว็บ) และ **Backend** (เซิร์ฟเวอร์ API)

---

## 📂 โครงสร้างของโปรเจกต์

- `frontend/`: ส่วนหน้าเว็บ พัฒนาด้วย **React** (Create React App)
- `backend/`: ส่วนเซิร์ฟเวอร์ พัฒนาด้วย **Node.js** และ **Express.js**

---

## 🚀 วิธีการรันโปรเจกต์ (Getting Started)

แอปพลิเคชันนี้จำเป็นต้องรันทั้งเซิร์ฟเวอร์และหน้าเว็บไปพร้อมๆ กัน (ต้องเปิด Terminal 2 หน้าต่าง)

### 1. รัน Backend (เซิร์ฟเวอร์)
1. เปิด Terminal แล้วเข้าไปที่โฟลเดอร์ backend:
   ```bash
   cd "c:\Data Praew\SecureNote\backend"
   ```
2. รันเซิร์ฟเวอร์ด้วยคำสั่ง:
   ```bash
   node server.js
   ```
   > เซิร์ฟเวอร์จะรันอยู่ที่พอร์ต `http://localhost:5000`

### 2. รัน Frontend (หน้าเว็บ)
1. เปิด Terminal ใหม่ (อีกหน้าต่าง) แล้วเข้าไปที่โฟลเดอร์ frontend:
   ```bash
   cd "c:\Data Praew\SecureNote\frontend"
   ```
2. เริ่มการทำงานของหน้าเว็บ:
   ```bash
   npm start
   ```
   > เบราว์เซอร์จะเปิดหน้าเว็บ `http://localhost:3000` ขึ้นมาโดยอัตโนมัติ

## ⚙️ การทำงานของระบบ Backend (Node.js API)

ส่วนของเซิร์ฟเวอร์ (`backend/server.js`) ทำหน้าที่จัดการข้อมูลโน้ตและให้บริการ API โดยมีระบบที่น่าสนใจดังนี้:

- **ระบบความปลอดภัย (Authentication):** มีการใช้ Middleware ชื่อ `authenticate` เพื่อคอยดักจับและตรวจสอบ `authorization` token ที่ส่งมาจากหน้าเว็บ หากค่า Token ไม่ตรงกับ `SECRET_TOKEN` ที่ตั้งไว้ในไฟล์ `.env` ระบบจะปฏิเสธการเพิ่มหรือลบโน้ตทันที (สถานะ `401 Unauthorized`)
- **การจัดเก็บข้อมูล (Data Storage):** ปัจจุบันข้อมูลโน้ตถูกเก็บไว้ใน Array ชั่วคราว (In-memory) ซึ่งเหมาะสำหรับการทดสอบระบบอย่างรวดเร็ว (ข้อมูลจะรีเซ็ตเมื่อปิดเซิร์ฟเวอร์)
- **การจัดเก็บข้อมูล (Data Storage):** ระบบได้เปลี่ยนมาใช้ฐานข้อมูล **SQLite** แล้ว โดยข้อมูลทั้งหมดจะถูกบันทึกไว้ในไฟล์ `backend/database.sqlite` ทำให้ข้อมูลโน้ตจะยังคงอยู่ถาวรแม้ว่าจะมีการรีสตาร์ทเซิร์ฟเวอร์ก็ตาม

**API Endpoints หลัก:**
- `GET /api/notes` - ดึงรายการโน้ตทั้งหมด (เปิดสาธารณะ ไม่ต้องใช้ Token)
- `POST /api/notes` - สร้างโน้ตใหม่ (ต้องยืนยันตัวตนด้วย Token)
- `DELETE /api/notes/:id` - ลบโน้ตตาม ID ที่ระบุ (ต้องยืนยันตัวตนด้วย Token)

## คำสั่งที่สามารถใช้งานได้ (Available Scripts)

ในไดเรกทอรีของโปรเจกต์ คุณสามารถรันคำสั่งเหล่านี้ได้:

### `npm start`

รันแอปพลิเคชันในโหมดนักพัฒนา (Development mode)\
เปิด http://localhost:3000 เพื่อดูในเบราว์เซอร์ของคุณ

หน้าเว็บจะรีโหลด (reload) อัตโนมัติเมื่อคุณแก้ไขและบันทึกโค้ด\
คุณยังสามารถดูคำเตือนและข้อผิดพลาด (lint errors) ได้ในหน้าจอคอนโซล

### `npm test`

เปิดโหมดทดสอบ (Test runner) แบบโต้ตอบ (interactive watch mode)\
ดูข้อมูลเพิ่มเติมเกี่ยวกับการ รันเทส (running tests) ได้ในเอกสารประกอบ

### `npm run build`

สร้างแอป (Build) สำหรับการนำไปใช้งานจริง (Production) ไว้ในโฟลเดอร์ `build`\
คำสั่งนี้จะทำการมัดรวม (bundle) React ในโหมด production และปรับแต่งโค้ดเพื่อให้ได้ประสิทธิภาพและทำงานได้เร็วที่สุด

ไฟล์บิลด์จะถูกบีบอัด (minified) และชื่อไฟล์จะมีแฮช (hashes) รวมอยู่ด้วย\
แอปของคุณพร้อมสำหรับการนำไปติดตั้งใช้งานจริง (deploy) แล้ว!

ดูหัวข้อ การนำขึ้นระบบ (deployment) สำหรับข้อมูลเพิ่มเติม

### `npm run eject`

**หมายเหตุ: นี่คือการดำเนินการที่ย้อนกลับไม่ได้ เมื่อคุณ `eject` แล้ว คุณจะไม่สามารถกลับมาใช้ค่าเริ่มต้นได้อีก!**

หากคุณไม่พอใจกับเครื่องมือ Build หรือการตั้งค่าที่โปรแกรมให้มา คุณสามารถใช้คำสั่ง `eject` ได้ตลอดเวลา คำสั่งนี้จะลบการพึ่งพาตัวบิลด์ (build dependency) ที่ซ่อนอยู่ออกจากโปรเจกต์ของคุณ

แต่มันจะคัดลอกไฟล์การตั้งค่าและ Dependencies ทั้งหมด (เช่น webpack, Babel, ESLint ฯลฯ) มาไว้ในโฟลเดอร์โปรเจกต์ของคุณโดยตรง เพื่อให้คุณควบคุมได้ทั้งหมด คำสั่งอื่นๆ (ยกเว้น `eject`) จะยังคงใช้งานได้ปกติ แต่จะชี้ไปยังสคริปต์ที่ถูกคัดลอกมา เพื่อให้คุณปรับแต่งมันได้ ถึงจุดนี้คุณจะต้องจัดการระบบ Build ทุกอย่างด้วยตัวเอง

คุณไม่จำเป็นต้องใช้คำสั่ง `eject` เลยก็ได้ ฟีเจอร์ที่เตรียมมาให้แต่แรกนั้นเหมาะสมเพียงพอสำหรับการใช้งานขนาดเล็กถึงขนาดกลาง และเราเข้าใจดีว่าบางคนอาจจะไม่ต้องปรับแต่งอะไร อย่างไรก็ตาม เราเตรียมคำสั่งนี้ไว้ให้ในกรณีที่คุณถึงจุดที่พร้อมและต้องการอิสระในการปรับแต่งเครื่องมือต่างๆ เอง
